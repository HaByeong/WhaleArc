① 포착 — 언제 끼어드나

사용자가 흔들리는 순간을 시스템이 먼저 감지해 말을 건다. 막지 않는다 — 묻고 기록만 한다.

트리거조건(예시)띄우는 메시지
급락 공포보유 자산 하루 −5% 이상"지금 팔고 싶으신가요?"
급등 탐욕(FOMO)미보유 자산 단기 +15% 급등"지금 올라타고 싶으신가요?"
규칙 위반 직전전략 신호와 반대 주문 시도"항로와 다른 방향이에요. 정말 가시겠어요?"
과잉 확인하루 차트 조회 N회 초과"오늘 벌써 12번 확인하셨어요. 불안하신가요?"

③ 개봉 — 4가지 경우의 수

규칙을 지켰든 어겼든 "안 한 쪽 결과"를 반드시 보여준다. 특히 충동이 옳았던 날도 정직하게 — 그래야 사용자가 믿는다.

선택결과메시지 톤
항로 지킴규칙이 옳았음"참길 잘했어요. 🐋"
항로 지킴충동이 옳았음"이번엔 충동이 맞았네요. 그래도 장기적으로 규칙이 이기는 이유는…"
충동 실행충동이 틀렸음"그때 흔들렸죠. 다음엔 한 박자 쉬어볼까요?"
충동 실행충동이 옳았음"운이 좋았어요. 같은 선택 10번 하면 몇 번 맞을까요?"

감정 패턴 대시보드 — 누적 거울

개별 사건이 쌓이면 "나라는 투자자"의 초상을 그려준다. 사용자가 계속 돌아오는 이유 = 자기 성장을 보는 맛.

데이터 모델 (개발용)

핵심 테이블 하나면 시작 가능. 포착 시 insert, 개봉은 스케줄러 배치로 결과 계산.

컬럼설명
trigger_typePANIC_DROP / FOMO_SPIKE / RULE_BREACH / OVER_CHECK
user_choiceFOLLOW_RULE / FOLLOW_IMPULSE
price_at_event / price_at_reveal봉인 시점 가격 / 개봉 시점 가격
impulse_outcome_pct / rule_outcome_pct충동대로 / 규칙대로 했을 때 수익률
reveal_at / is_revealed개봉 예정 시점 / 개봉 여부
emotion_note / emotion_intensity감정 메모 / 강도(1~5)

스택: 포착 = 프론트 인터셉트 + 백엔드 API / 개봉 = @Scheduled 배치 / 대시보드 = 집계 쿼리. 시세는 모의투자용을 재사용 → 새 인프라 거의 없음.

MVP 범위 — 자르는 순서

단계범위
MVP트리거 1개(급락 공포)만 · 포착 → 봉인 → 7일 뒤 개봉 · 두 결과 대조. 대시보드 없음.
v2트리거 4개 전부 · 감정 메모/강도 · 누적 대시보드
v3"가장 약한 순간" 분석 · AI가 패턴 코멘트(프로그램 AI솔루션 활용처)
심사·IR 팁 — MVP 데모 하나면 충분하다. "급락 때 팔고 싶었던 순간이 7일 뒤 열려서, 안 판 게 +3%였다고 보여준다" — 이 한 장면이면 심사위원이 "오" 한다.

톤 — 성패가 여기 달렸다

  • ❌ 혼내지 마라 — "또 충동매매 하셨네요"는 죽음. 사용자가 떠난다.
  • ✅ 거울이 되어라 — 판단은 사용자가, 시스템은 사실만 비춘다.
  • ✅ 충동이 옳았던 날은 정직하게 인정 — 그래야 믿음이 생긴다.
  • ✅ 고래 서사 유지 — "흔들렸다 / 항로 / 유영"을 일관되게.
왜 이게 WhaleArc의 유일한 장점인가 — 백테스트·모의투자는 남들도 한다. 하지만 투자자 자신의 감정을 거울처럼 비춰주는 건 당신만 한다. 경쟁사가 기능은 베껴도 "투기를 투자로"라는 서사가 없으면 어색하다. 차별점이 기능이 아니라 정체성에 박혀 있다.
